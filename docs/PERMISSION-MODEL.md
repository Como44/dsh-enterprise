# PERMISSION-MODEL —— 权限模型

> 两层权限：**DSH 执行层权限**（allow/ask/deny/sandbox，已存在，不动它）与**企业层角色权限**（本模型，决定"谁能看/用/改/发布/授权"）。

## 1. 角色（人话）

| 角色 | 一句话 | 对应的人 |
|---|---|---|
| Owner | 公司老板：一切权限 | 创建企业的人 |
| Admin | 管理员：管理成员、资产、预算、连接 | 指定管理员 |
| Member | 员工：使用企业资产，管理自己的私有资产 | 普通成员 |

## 2. 五轴权限（MVP 规则表）

| 操作 | Owner | Admin | Member |
|---|---|---|---|
| 查看企业空间/资产/用量 | ✅ | ✅ | ✅（用量只看自己 + 企业总览只读） |
| 会话（自己） | ✅ | ✅ | ✅ |
| 创建私有资产（Agent/Skill 发布、知识目录） | ✅ | ✅ | ✅（默认个人私有） |
| 发布资产为企业共享 / 撤回 | ✅ | ✅ | ❌（可申请，P2 审核） |
| 推荐资产 / 设企业默认 | ✅ | ✅ | ❌ |
| 编辑/归档/删除企业资产 | ✅ | ✅ | ❌（创作的企业资产：仅 Admin/Owner 可撤） |
| 成员管理（邀请/删除/改角色） | ✅ | ✅ | ❌ |
| 预算与额度设置 | ✅ | ✅（成员额度需 Owner） | ❌ |
| 外部账号管理（连接/绑定 Agent/撤权） | ✅ | ✅ | ✅（创建自己的连接，需 Admin 审核绑定 P2） |
| 企业设置 | ✅ | ❌ | ❌ |
| 审计详情（全体会话） | ✅ | ✅ | ❌ |

## 3. 资产归属与可见性（组合规则）

```text
资产 = 归属（organization | personal） × 共享状态（personal | enterprise） 
```

- `organization + enterprise`：企业全员可用（默认期望态）；
- `organization + personal`：企业持有但仅创建者可见（草稿/私有化）；
- `personal + personal`：个人私有，不随企业（离职归个人，产品决策，见 ASSET-MODEL）；
- `personal → enterprise` 的发布动作：MVP 由 Admin 一键确认（无审核流），P2 支持审核。

## 4. 与 DSH 执行权限的关系

- DSH 的 `approval`/`sandbox`/`permissionPresets` 继续按会话生效（企业层**不拦截、不绕过**）；
- 企业层新增的是「可见性政令」：Member 只能看到/使用被允许的企业资产与连接的绑定关系；
- 一致性约束：**资产可见 ≠ 资产可执行**。Member 能看到企业 Skill，但执行仍需 DSH 侧技能权限（若部署了限制）。

## 5. 已知边界（诚实标注）

- MVP 的"成员"是**产品内身份**（DSH 本机单用户，成员表为演示映射，UI 有标注）；
- 真实多用户接入后，本表升级为「网关心跳身份 → memberId」映射，规则不变；
- 不做精细 RBAC（部门/资源级 ACL）——P2 再用同一张表扩展 `scope` 列。
